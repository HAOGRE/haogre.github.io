# 可导流 404 页面设计

## 背景

GA4 显示最近一段时间大量访问落到 `404 Not Found | HAOGRE`。当前 404 页面只有返回首页入口，无法帮助误入旧链接的访问者继续浏览。

## 目标

- 保留真实的 HTTP 404 语义，避免把不存在的 URL 伪装成有效首页。
- 为误入页面的访问者提供明确的下一步路径。
- 复用现有博客的多语言、布局和文章排序逻辑。
- 不对未知 URL 做全量 301/302 跳转。

## 方案

改造 `src/pages/404.astro`：

1. 保留现有 404 标题和说明。
2. 增加站内搜索入口，链接到当前语言的搜索页。
3. 增加“最近文章”区块，展示当前语言最近 3 篇可发布文章。
4. 保留返回首页和查看全部文章入口。
5. 使用现有 `getSortedPosts`、`Card` 或等价的现有组件，避免新建独立文章查询逻辑。
6. 在中文和英文翻译文件中补充 404 导流文案。

## 数据流

构建时从 `posts` collection 读取当前语言文章，经过现有 `postFilter` 和 `getSortedPosts` 过滤排序，取前 3 篇渲染到静态 404 页面。页面继续由 Astro 以 404 路由输出，GA4 继续记录访问行为。

## 不在本次范围

- 不将所有未知 URL 重定向到首页。
- 不批量猜测旧 URL 的文章映射。
- 不新增热门文章统计或运行时 API。
- 不改变已有文章 URL、canonical 或 sitemap。

## 验证

- `npm run build` 或至少执行 Astro 类型检查，确认中文/英文 404 页面均能生成。
- 检查生成的 404 页面包含搜索、首页、全部文章和 3 篇文章链接。
- 确认未知 URL 仍返回 404，而不是 200 或重定向。
