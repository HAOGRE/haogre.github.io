“视频播放不了”描述的是最终结果。文件拿不到、MP4 结构读不懂、解码器处理不了，都可能留下相似的黑屏。换浏览器、清缓存、转格式，如果没有先区分失败发生在哪一步，很容易变成反复试运气。

最近遇到的两段视频就是这样：同为 MP4，同为 HEVC 和 AAC，一段能播，另一段失败。最后通过对照实验，发现失败文件中的一条额外元数据轨道触发了浏览器解析错误。这个过程让我重新整理了播放链路里几个容易混在一起的问题。

## 下载成功，只说明拿到了文件

网页能打开，不代表视频资源能被读取。视频通常是单独的请求，可能使用另一个资源地址，还可能带有临时签名。

检查时需要区分状态码、响应体和请求方法。一次 `HEAD` 请求返回 403，并不能单独证明播放器用 `GET` 请求也会被拒绝。有些签名会绑定请求方法。这次排查中就遇到了 HEAD 返回 403，而带 Range 的 GET 成功返回 206 的情况。

下面是示意命令，地址使用保留给文档示例的域名：

```bash
curl --fail --silent --show-error \
  --range 0-1023 \
  -D response-headers.txt \
  -o first-bytes.bin \
  'https://media.example.com/video.mp4'
```

`206 Partial Content` 配合正确的 `Content-Range`，说明服务端返回了所请求的字节段。还要确认内容确实来自媒体文件，不能把一段错误页面因为后缀叫 `.mp4` 就当成视频。

本机命令行请求成功，也不等于网页请求一定成功。浏览器还有自身的安全策略、身份状态和请求上下文，需要结合实际页面继续判断。

## MP4 是封装，HEVC 才是视频编码

文件名里的 `.mp4` 没有告诉我们画面是怎样压缩的。一个 MP4 里可以装 H.264，也可以装 HEVC，还可能包含音频、字幕和元数据。

用 ffprobe 可以先看轨道，而不是只看文件后缀：

```bash
ffprobe -v error \
  -show_entries stream=index,codec_type,codec_name,codec_tag_string,profile \
  -of json input.mp4
```

这次失败的样本除了 HEVC 视频和 AAC 音频，还列出了一条 `codec_type=data`、`codec_tag_string=mebx` 的轨道。它给出了一个值得检查的差异，但 ffprobe 能列出轨道，不等于已经证明浏览器能正确处理它。

## 解封装失败和解码失败，要分开处理

解封装负责从文件里取出音视频样本，解码负责把压缩数据还原成画面和声音。两步都有自己的兼容性边界。

在这次本机对照实验里，浏览器报的是：

```text
DEMUXER_ERROR_COULD_NOT_OPEN
FFmpegDemuxer: open context failed
```

它指向容器解析阶段。此时检查 MP4 的轨道结构，比继续猜测 HEVC 的硬件支持更直接。

反过来，如果容器已经打开，拿到了轨道信息，随后才出现解码错误，就需要继续检查具体码流、Profile、位深以及实际解码路径。不能把一个宽泛的播放器错误码当成完整结论，详细错误消息和对照结果更有用。

## 本地能解码，也只是一个边界条件

下面的命令可以完整解码主视频和可选音轨，并丢弃输出：

```bash
ffmpeg -v error -i input.mp4 \
  -map 0:v:0 -map '0:a:0?' -f null -
```

两段样本都通过了这项检查。这帮助排除了“当前 FFmpeg 连文件都读不出来”这类情况，但不能代替浏览器验证。浏览器内置的 FFmpeg 构建、系统解码能力和本机安装的命令行版本可能不同。

所以处理后的文件还要回到目标播放器里验证。能看到时长只说明元信息读出来了，播放进度持续前进、可以拖动、音画同步，才覆盖了更多实际使用路径。

## 修复有效以后，再确认改对了哪里

重新封装时可能同时去掉额外轨道、重写时间信息、调整索引位置。一次处理成功，不能把所有改动都写成根因。

这个案例补做了两个实验：索引仍在末尾的重新封装文件能正常加载；原文件只忽略那条元数据轨道后，播放进度超过了 7 秒。后一个实验把原因缩到了具体轨道。它也保留了一个边界：尚未确定轨道内部究竟哪个字段让解析器失败。

给故障下结论时，把“已经观察到”“实验已验证”和“还没检查”分开写，比再加一句“应该是兼容性问题”更方便后续处理。

AI 在这里帮了很大的忙。请求检查、轨道分析、完整解码和浏览器对照原本分散在几个工具里，它把这些操作接起来，让每一步都有结果可以继续判断。能把一句模糊的“播放不了”查到具体失败环节，这种执行能力确实很强。
